- Notação Big O, o que é? 
  Uma forma de MEDIR o NÚMERO DE OPERAÇÕES de acordo com o aumento da quantidade de dados (n), focando na
  escalabilidade do algorítmo, e não no tempo em segundos.

- Complexidades de tempo:
    
    Da mais rápida até a mais lenta:

    O(1) - Tempo constante (ou instantâneo):

        Não importa se nossa estrutura tem 1 ou 1 bilhão de elementos, o tempo gasto para percorrer e encontrar determinado
        item será o mesmo para todos.

        Ex.
            1. Acessar um elemento em uma array pelo indice (arr[3]).

        Uma boa ideologia para facilitar a compreensão é a ideia da pilha de livros, se pegarmos o primeiro item dessa pilha
        (indepentende do tamanho que ela tenha) sempre precisaremos executar um único movimento por vêz.

    O(log n) - Tempo logarítmico:

        A cada passo que o algorítmo dá, descartamos metade dos dados restantes, o número de operações cresce de forma extremamente lenta
        a medida que {n} aumenta

        Ex.
            1. Busca binária em arrays ORDENADOS
            2. Inserção, remoção e busca em Árvores Binárias de Busca BALANCEADAS (como a AVL ou Red Black)

        Imagine que temos uma lista telefonica x onde queremos encontrar y mas ela possui 1000 páginas, para poupar tempo e processamento
        (isso se a lista estiver ordenada) dividimos a lista em 2 conferimos se y vem antes ou depois da metade dividida. Indepentende de qaal
        lado esteja, discartaremos o item central da busca + a outra metade (ou seja, 501) repetimos o processo e em 5 passos ou menos encontraremos
        o determinado valor no qual a pior das hipóteses para encontra-lo seria percorrer TODOS os 1000 itens até achar y. O que seria ilógico já
        que esse exemplo em específico possui 1000 itens, mas e se possuisse 1 milhão? 1 bilhão? Ou seja, o tempo e processamento que essa complexidade
        nos garante é totalmente relevante. 

    O(n) - Tempo linear (ou proporcional):

        Se a quantidade de dados presentes na estrutura dobra, o tempo gasto também dobra. Usando uma relação sempre de 1 para 1.

        Ex.
            1. Buscar um valor em uma Lista Encadeada ou um Array desordenado.
            2. Percorrer todos os elementos de uma árvore ou vetor

        Podemos exemplificar com uma pilha de documentos desorganizados por exemplo, para achar uma anotação específica, teriamos de seguir justamente 
        esse conceito de tempo linear.

    O(n log n) - Tempo linearítmico (ou padrão de ouro para ordenar):

        Essa complexidade se torna pouca coisa mais lenta que o LINEAR O(n). Mas ainda muito eficiente. Geralmente resulta da combinação de dividir o problema pela metade

        (O(log n)) e passar por todos os elementos (O(n)).
        Ex.
            1. Algoritmos eficientes de ordenação como Merge Sort, QuickSort (no caso médio) e Heap Sort:

                https://www.youtube.com/results?search_query=Merge+Sort
                https://www.youtube.com/watch?v=wx5juM9bbFo&pp=ygUKcXVpY2sgc29ydA%3D%3D
                https://www.youtube.com/watch?v=fZQgE8fYVy4&pp=ygUKaGVhcCBzb3J0IA%3D%3D

    O((log n)² ou O(log² n)) - Tempo poligarítmico (log ao quadrado):

        Para a compreensão deste, basta apenas saber que sua propriedade se dá em elevar a complexidade logarítmica ao quadrado: (log n) * (log n)

        Ex.
            Se n = 1.000.000
            log de n na base 2 = 20

            Já o (log de n na base 2)² = 400

            Esse é um pouco mais lento que O(log n) ou O(n), mas infinitamente mais rápido que O(n²) para entradas grandes
        
        Costuma ser usado em estruturas de dados avançadas para busca multidimensional (como Range Trees de duas dimensões) ou algoritmos de ordenação em redes paralelas
        (como o Bitonic Sort): https://www.youtube.com/watch?v=xBgkUAPbcKk&pp=ygUMQml0b25pYyBTb3J0
        
    O(n²) - Tempo quadrático (o "lento"):

        Para cada elemento de uma determinada lista, precisamos iterar sobre todos os outros elementos novamente, caso os dados dobrem (2n), o tempo quadruplica (4*).

            Ex.
                1. Dois laços de repetição aninhados (for dentro de for)
                2. Algoritmos simples de ordenação como Bubble Sort, Selection Sort e Insertion Sort

                    https://www.youtube.com/watch?v=GiNPe_678Ms&pp=ygULQnViYmxlIFNvcnQ%3D
                    https://www.youtube.com/watch?v=ZT_dT8yn48s&t=2s&pp=ygUOc2VsZWN0aW9uIHNvcnQ%3D
                    https://www.youtube.com/watch?v=S5no2qT8_xg&pp=ygUbaW5zZXJ0aW9uIHNvcnQgYWxnb3JpdG1hc8Sx

        Imagine que uma sala tem x pessoas, cada pessoa precisa cumprimentar individualmente todas as outras.

    O(2°) e O(n!) - Exponencial e fatorial (o inviável):

        Significa que o número de operações explode absurdamente rápido. A partir de n = 3o ou n = 50, o algorítmo pode levar milênios, indepentende do
        supercomputador.

            Ex.
                1. Gerar todos os subconjuntos de um conjunto (O(2°))
                2. Resolver o problema do Caixeiro Viajante testando todas as combinações por força bruta (O(n!))

                    https://search.brave.com/search?q=caixeiro+viajante+algoritmo&conversation=096daca7baaca4527ab37e3906ba5863592e

Comparativo prático para (n = 1000 elementos):

    Notação             Nome                N° Aproximado de passos

    O(1)                Constante           1 passo

    O(log n)            Logarítmico         ~10 passos

    O(log² n)           Polilogarítmico     ~100 passos

    O(n)                Linear              1.000 passos

    O(n log n)          Linearítmico        ~10.000 passos

    O(n²)               Quadrático          1.000.000 passos
    
    O(2°) ou O(n!)      Exponencial         10301 passos
